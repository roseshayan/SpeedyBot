# ربات تلگرام فروش خودکار X-UI / سنائی

این پروژه یک ربات تلگرام برای فروش خودکار سرویس‌های X-UI / پنل سنائی 3.3.0 است.  
فرآیند کار به این شکل است:

1. نمایش پلن‌ها به کاربر
2. دریافت عکس فیش واریزی
3. بررسی دستی توسط ادمین
4. ساخت خودکار اکانت در پنل
5. ارسال لینک سابسکریپشن و کانفیگ مستقیم برای کاربر

کاربر همچنین می‌تواند مستقیماً از منوی ربات یک **تست رایگان ۱ گیگابایت با اعتبار ۱ روز** دریافت کند. هر Telegram User ID فقط یک‌بار امکان دریافت تست دارد.

داده‌های ربات در **SQLite** ذخیره می‌شوند و اجرای آن با **systemd** روی اوبنتو انجام می‌شود.

## محیط تست

- Ubuntu 24.04
- پنل Sanaei 3.3.0
- Python 3
- `pyTelegramBotAPI`
- `requests`

## امکانات ربات

- نمایش منوی ساده برای کاربران
- نمایش اطلاعات کارت و حساب واریز
- دریافت عکس فیش پرداخت
- ارسال فیش برای ادمین
- تایید یا رد پرداخت توسط ادمین
- ساخت خودکار کلاینت در پنل X-UI پس از تایید
- صدور خودکار تست رایگان ۱GB / ۱ روز بدون نیاز به تایید ادمین
- جلوگیری از دریافت چندباره تست با ثبت دائمی سابقه در SQLite
- Retry امن در صورت خطای پنل، بدون ساخت کلاینت تکراری
- نمایش تست صادرشده در بخش «حساب کاربری» و استعلام وضعیت زنده آن
- تولید:
  - لینک سابسکریپشن
  - لینک‌های کانفیگ مستقیم
- سیستم پشتیبانی داخلی
- پنل مدیریت با دستور `/sudoadmin`
- نمایش تعداد تست‌های صادرشده در آمار پنل مدیریت

## تست رایگان

دکمه `🎁 دریافت تست رایگان` در منوی اصلی قرار دارد. با انتخاب آن:

1. ربات بررسی می‌کند کاربر قبلاً تست گرفته است یا خیر.
2. یک کلاینت با نام `speedping_trial_<telegram_user_id>` در پنل ساخته می‌شود.
3. سقف ترافیک روی ۱ گیگابایت قرار می‌گیرد.
4. تاریخ انقضا ۲۴ ساعت بعد تنظیم می‌شود.
5. لینک سابسکریپشن و کانفیگ‌های مستقیم برای کاربر ارسال می‌شوند.
6. سابقه تست مستقل از جدول کاربران ذخیره می‌شود؛ بنابراین حذف کاربر از لیست ربات باعث فعال شدن تست مجدد نمی‌شود.

اگر ارتباط با پنل در میانه صدور قطع شود، وضعیت درخواست `FAILED` می‌شود و کاربر می‌تواند دوباره تلاش کند. در Retry ابتدا وجود کلاینت قبلی بررسی می‌شود تا اکانت تکراری ساخته نشود.

## پیش‌نیازها

شما به این موارد نیاز دارید:

- توکن ربات تلگرام از BotFather
- آیدی عددی ادمین تلگرام
- توکن ادمین پنل X-UI / سنائی
- آدرس API پنل
- بیس‌پث امنیتی پنل
- آدرس سرور سابسکریپشن برای لینک‌های `/sub/...`

### متغیرهای محیطی

ربات این متغیرها را از محیط اجرا می‌خواند:

- `BOT_TOKEN`
- `ADMIN_ID`
- `XUI_API_URL`
- `XUI_BASE_PATH`
- `XUI_BEARER_TOKEN`
- `XUI_SUB_SERVER_URL`

نمونه:

```bash
BOT_TOKEN=123456:ABCDEF...
ADMIN_ID=123456789
XUI_API_URL=http://127.0.0.1:2053
XUI_BASE_PATH=/
XUI_BEARER_TOKEN=your-panel-bearer-token
XUI_SUB_SERVER_URL=https://sub.example.com:2096
```

### نکات مهم درباره مقادیر پنل

- `XUI_API_URL` باید همراه با پروتکل و پورت باشد.
- `XUI_BASE_PATH` باید دقیقاً با مسیر امنیتی پنل یکی باشد.
  - اگر پنل مسیر امنیتی ندارد، از `/` استفاده کنید
  - اگر دارد، چیزی شبیه `/your-secret-base-path` وارد کنید
- `XUI_SUB_SERVER_URL` برای ساخت لینک‌هایی مثل زیر استفاده می‌شود:
  `https://sub.example.com:2096/sub/<id>`

## نصب روی Ubuntu 24.04

### روش اول: نصب خودکار

فایل‌های پروژه را روی سرور قرار دهید و این دستور را اجرا کنید:

```bash
chmod +x install.sh
sudo ./install.sh
```

اسکریپت نصب از شما این اطلاعات را می‌پرسد:

- توکن ربات
- آیدی ادمین
- آدرس API پنل
- بیس‌پث پنل
- توکن Bearer پنل
- آدرس سرور سابسکریپشن

سپس این کارها را انجام می‌دهد:

- نصب پکیج‌های پایتون
- ساخت دایرکتوری `/root/SpeedyBot`
- کپی کردن `main.py`
- ساخت virtualenv
- نصب وابستگی‌ها
- ساخت سرویس `systemd` با نام `xui-bot.service`
- فعال و اجرا کردن سرویس

### روش دوم: نصب دستی

پکیج‌های سیستم را نصب کنید:

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv
```

پوشه کاری را بسازید:

```bash
sudo mkdir -p /root/SpeedyBot
sudo cp main.py /root/SpeedyBot/main.py
cd /root/SpeedyBot
```

محیط مجازی و وابستگی‌ها را نصب کنید:

```bash
python3 -m venv .venv
./.venv/bin/pip install --upgrade pip
./.venv/bin/pip install pyTelegramBotAPI requests
```

فایل سرویس systemd را بسازید:

```bash
sudo nano /etc/systemd/system/xui-bot.service
```

و این محتوا را داخل آن قرار دهید:

```ini
[Unit]
Description=X-UI Telegram Shop Bot Service
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/SpeedyBot
ExecStart=/root/SpeedyBot/.venv/bin/python3 /root/SpeedyBot/main.py
Restart=always
RestartSec=5
Environment=BOT_TOKEN=YOUR_BOT_TOKEN
Environment=ADMIN_ID=YOUR_ADMIN_ID
Environment=XUI_API_URL=YOUR_XUI_API_URL
Environment=XUI_BASE_PATH=YOUR_XUI_BASE_PATH
Environment=XUI_BEARER_TOKEN=YOUR_BEARER_TOKEN
Environment=XUI_SUB_SERVER_URL=YOUR_SUB_SERVER_URL

[Install]
WantedBy=multi-user.target
```

سرویس را فعال و اجرا کنید:

```bash
sudo systemctl daemon-reload
sudo systemctl enable xui-bot.service
sudo systemctl start xui-bot.service
```

بررسی وضعیت و لاگ:

```bash
sudo systemctl status xui-bot.service
sudo journalctl -u xui-bot.service -f
```

## روند کار کاربر

### 1) ورود به ربات
کاربر `/start` می‌زند و منوی اصلی را می‌بیند.

### 2) انتخاب پلن
ربات پلن‌های تعریف‌شده در `PLANS` داخل `main.py` را نمایش می‌دهد.

پلن پیش‌فرض فعلی:

```python
1: {"name": "پلان نامحدود (یک‌ماهه)", "price": 300000, "volume": 0, "days": 30}
```

### 3) پرداخت دستی
ربات اطلاعات کارت و بانک را از دیتابیس SQLite می‌خواند و نشان می‌دهد.

### 4) ارسال فیش پرداخت
کاربر باید **عکس** فیش را به صورت Reply به همان پیام ارسال کند.

اگر متن بفرستد و عکس نفرستد، ربات آن را رد می‌کند.

### 5) بررسی توسط ادمین
فیش برای ادمین فوروارد می‌شود و دو دکمه دارد:

- تایید پرداخت
- رد فیش

### 6) ساخت خودکار سرویس
وقتی ادمین فیش را تایید کند:

- برای کاربر یک ایمیل/شناسه به شکل زیر ساخته می‌شود:
  `speedping_<telegram_id>_<transaction_id>`
- ربات همه اینباندهای فعال را از پنل می‌خواند
- کلاینت جدید روی آن اینباندها ساخته می‌شود
- لینک‌های اتصال گرفته می‌شوند
- برای کاربر ارسال می‌شود:
  - لینک سابسکریپشن
  - لینک‌های مستقیم

پنل باید این مسیرها را دقیقاً همان‌طور که در پروژه استفاده شده پشتیبانی کند.

# سیستم همکاری در فروش و کیف پول — نسخه 2.0

نسخه 2.0 یک سیستم همکاری در فروش تک‌سطحی و کیف پول داخلی به ربات اضافه می‌کند.

## رفتار سیستم معرفی

- هر کاربر یک کد و لینک دعوت دائمی و تصادفی دارد.
- لینک به شکل `https://t.me/BOT_USERNAME?start=ref_CODE` ساخته می‌شود.
- فقط **اولین ورود واقعی یک کاربر جدید** می‌تواند معرف او را ثبت کند.
- کاربری که قبلاً وارد ربات شده باشد با باز کردن لینک دعوت شخص دیگر، معرفش تغییر نمی‌کند.
- خودمعرفی با همان Telegram User ID مسدود است.
- سیستم تک‌سطحی است و MLM / پورسانت چندسطحی ندارد.
- دریافت تست رایگان هیچ پورسانتی ایجاد نمی‌کند.
- نرخ پورسانت پیش‌فرض `10%` است و از پنل `/sudoadmin` قابل تغییر است.
- پورسانت بر اساس مبلغ نقدی/کارت خرید موفق محاسبه می‌شود.
- خریدی که کاملاً با کیف پول انجام شود پورسانت جدید تولید نمی‌کند تا چرخه اعتبار مصنوعی ایجاد نشود.
- پورسانت تنها پس از **صدور موفق سرویس X-UI** ثبت می‌شود، نه صرفاً بعد از کلیک ادمین روی تایید فیش.
- برای هر تراکنش خرید فقط یک رکورد پورسانت می‌تواند وجود داشته باشد؛ Retry یا Restart باعث دوباره شارژ شدن کیف پول نمی‌شود.

## کیف پول

در منوی `🤝 همکاری در فروش` کاربر موارد زیر را می‌بیند:

- موجودی فعلی کیف پول
- تعداد دعوت‌شده‌ها
- تعداد کاربران دعوت‌شده‌ای که خرید موفق داشته‌اند
- مجموع پورسانت دریافت‌شده
- درصد پورسانت فعلی
- لینک اختصاصی دعوت
- دکمه اشتراک‌گذاری لینک
- ۱۵ تراکنش آخر کیف پول

اگر موجودی کیف پول حداقل به قیمت یک پلن برسد، در بخش خرید دکمه `پرداخت از کیف پول` نمایش داده می‌شود و سرویس بدون ارسال فیش بانکی صادر می‌شود.

تمام تغییرات کیف پول در جدول ledger مستقل ثبت می‌شوند و فقط مقدار `balance` ملاک نیست؛ بنابراین شارژ، کسر، خرید، پورسانت و بازپرداخت قابل حسابرسی هستند.

## حفاظت در برابر خطا و سوءاستفاده

- معرف بعد از ثبت قابل تغییر نیست.
- حذف کاربر از پنل مدیریت به صورت Soft Deactivate انجام می‌شود و رکورد کاربر از دیتابیس حذف نمی‌شود؛ در نتیجه حذف و `/start` مجدد باعث پاک شدن سابقه تست یا معرف نمی‌شود.
- صدور سرویس پولی idempotent شده است؛ Retry ابتدا وجود کلاینت را روی X-UI بررسی می‌کند و کلاینت تکراری نمی‌سازد.
- اگر سرویس در حین صدور خطا بخورد، تراکنش به وضعیت `ISSUE` می‌رود و ادمین دکمه Retry دریافت می‌کند.
- برای خرید کیف پولی که در وضعیت ISSUE مانده، ادمین دکمه بازپرداخت دارد؛ ربات پیش از بازپرداخت بررسی می‌کند که کلاینت روی X-UI وجود نداشته باشد.
- اگر سرور یا ربات وسط صدور ری‌استارت شود، تراکنش‌های `PROCESSING` در شروع بعدی بازیابی می‌شوند.
- اگر ربات دقیقاً بعد از APPROVED شدن خرید و قبل از واریز پورسانت خاموش شود، در شروع بعدی پورسانت‌های جاافتاده reconcile می‌شوند.
- کلیک پشت‌سرهم روی خرید کیف پول برای همان پلن در بازه کوتاه مسدود شده است.

> توجه: هیچ ربات تلگرامی نمی‌تواند تشخیص دهد دو Telegram Account مختلف متعلق به یک انسان هستند. این نسخه سوءاستفاده در سطح Telegram User ID، تراکنش و دیتابیس را کنترل می‌کند و پورسانت را فقط به خرید واقعی متصل می‌کند.

## عیب‌یابی اتصال به 3x-ui

نسخه 2.1.0 مطابق REST API جدید 3x-ui از Bearer Token استفاده می‌کند. Token باید **خود مقدار plaintext تولیدشده** در `Settings → Security → API Token` باشد؛ نام Token یا Web Base Path معتبر نیست. مقدار plaintext فقط هنگام ساخت Token نمایش داده می‌شود.

بعد از نصب، ادمین می‌تواند در تلگرام دستور زیر را اجرا کند:

```text
/xuidiag
```

این دستور فقط دو درخواست Read-only به Inbounds و Clients می‌فرستد و هیچ تنظیمی را تغییر نمی‌دهد.

کدهای رایج:

- `HTTP 200 / success=true`: اتصال و Bearer Token صحیح است.
- `401/403`: Token اشتباه، غیرفعال یا از دست رفته است.
- `404`: Web Base Path، نسخه پنل یا Reverse Proxy اشتباه است.
- `5xx`: خطا از پنل یا Reverse Proxy است.

در نسخه‌های جدید 3x-ui، اگر به SSH همان سرور پنل دسترسی دارید می‌توانید با دستور زیر یک API Token جدید تولید کنید؛ مقدار plaintext نمایش‌داده‌شده را همان لحظه ذخیره کنید:

```bash
x-ui setting -getApiToken
```

اگر نسخه پنل این فلگ را نداشت، از رابط پنل در `Settings → Security → API Token` یک Token جدید بسازید.

مسیر Subscription نیز قابل تنظیم است و در `.env` با `XUI_SUB_PATH` ذخیره می‌شود؛ مقدار پیش‌فرض `/sub/` است.
