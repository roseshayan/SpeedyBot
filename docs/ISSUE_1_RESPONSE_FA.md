# پاسخ پیشنهادی به Issue #1 — لینک اشتراک / Trial Inbounds

سلام، ممنون که با جزئیات گزارش دادی 🙏

مشکل لینک‌های تست رایگان بررسی شد. در نسخه **v3.1.0** مسیر تحویل کانفیگ Trial اصلاح شده است. از این نسخه، کانفیگ‌های مستقیم از endpoint رسمی لینک Client در 3x-ui گرفته می‌شوند و URL سابسکریپشن دیگر به‌عنوان کانفیگ مستقیم نمایش داده نمی‌شود. خروجی Direct فقط Schemeهای واقعی مثل `vless://`، `vmess://`، `trojan://`، `ss://` و Hysteria را قبول می‌کند.

همچنین پیشنهادهای شما هم اضافه شدند:

- انتخاب Inboundهای مخصوص **Trial** از پنل ادمین؛
- انتخاب Inboundهای مستقل برای **هر Plan ID**؛
- امکان Reset هر پلان/Trial روی همه Inboundهای فعال؛
- روشن/خاموش کردن کامل **تست رایگان** از `/sudoadmin`؛
- در Retry، اگر Client قبلاً ساخته شده باشد Inboundهای آن دوباره با تنظیم فعلی Sync می‌شوند؛
- Renewal هم می‌تواند Inboundهای سرویس را با پلان جدید هماهنگ کند.

بعد از آپدیت لطفاً از مسیر زیر Inboundهای موردنظرت را انتخاب کن:

`/sudoadmin → 🧪 تست و Inboundها`

بعد با یک Telegram ID که قبلاً Trial نگرفته، تست جدید بگیر و Direct Linkها را با گزینه **Copy URL** همان Client در 3x-ui مقایسه کن. اگر Host در هر دو جا اشتباه بود، مشکل از Share Address/Public Host خود Inbound در پنل است و باید همان‌جا اصلاح شود.

اگر بعد از v3.1.0 هنوز اختلافی دیدی، لطفاً این موارد را داخل Issue بفرست (بدون Token و بدون لینک کامل کانفیگ):

1. نسخه 3x-ui؛
2. Protocol و ID Inbound؛
3. بخش Domain/IP را Mask کن و فقط ساختار تفاوت را نشان بده؛
4. خروجی `/xuidiag`؛
5. حدود 50 خط آخر `journalctl -u xui-bot.service` با حذف اطلاعات حساس.

ممنون بابت Report و پیشنهاد خوبت؛ همین بازخوردها باعث بهتر شدن پروژه می‌شوند. ⚡️
