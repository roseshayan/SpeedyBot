ربات متن‌باز تلگرام برای 3x-ui

فروش و مدیریت سرویس در تلگرام

SpeedyBot پس از تأیید پرداخت در 3x-ui سرویس می‌سازد و لینک سابسکریپشن و کانفیگ را به مشتری تحویل می‌دهد. مشتری می‌تواند مصرفش را ببیند، سرویس را تمدید کند یا درخواست پشتیبانی بفرستد.

SpeedyBot چه کار می‌کند؟

فروش و تحویل

خرید با رسید کارت‌به‌کارت یا کیف پول، صدور تست، تمدید همان سرویس، فروش حجم برای پلان‌های محدود و تحویل سابسکریپشن، لینک مستقیم و QR.

حساب کاربری

مشاهدهٔ زمان و حجم باقی‌مانده، سوابق خرید و کیف پول، بازیابی لینک‌ها، راهنمای اتصال، پشتیبانی و اتصال سرویس قبلی با بررسی مالکیت.

مدیریت و نگهداری

قیمت و دسته‌بندی پلان‌ها، انتخاب Inbound، عضویت اجباری، کد هدیه و تخفیف، معرفی، نظرسنجی، اعلان مصرف و انقضا، بکاپ و گزارش فروش.

نصب روی سرور

این مسیر برای نصب تازه روی Ubuntu یا Debian با systemd است. Ubuntu 24.04 LTS و Python 3.11 یا بالاتر پیشنهاد می‌شود. برای نصب موجود از به‌روزرسان استفاده کن.

آماده‌سازی

  1. در BotFather دستور /newbot را بزن و توکن را نگه دار. شناسهٔ عددی حساب مالک ربات را آماده کن. اگر به آن دسترسی نداری، قبل از اجرای ربات یک پیام خصوصی برای آن بفرست و در پاسخ getUpdates مقدار message.from.id را پیدا کن.
  2. در 3x-ui از Settings → Security → API Token یک توکن بساز و مقدار کامل آن را بردار. حداقل یک Inbound را فعال کن و آدرس و مسیر Subscription را در تنظیمات پنل بررسی کن.
  3. از سرور به Telegram Bot API و آدرس API پنل دسترسی خروجی داشته باش. مشتری‌ها هم باید بتوانند به آدرس عمومی سابسکریپشن وصل شوند. ربات از polling استفاده می‌کند و برای آن به پورت وب‌هوک نیاز نداری.

اجرای نصب‌کننده

با sudo -i وارد حساب root شو و دستورهای زیر را به‌ترتیب اجرا کن. ورود توکن‌ها هنگام تایپ نمایش داده نمی‌شود.

Bash
apt update
apt install -y git
git clone https://github.com/roseshayan/SpeedyBot.git /root/SpeedyBot
cd /root/SpeedyBot
bash install.sh

برای https://panel.example.com:2053/private/ مسیر /private را در فیلد مجزا وارد کن. برای آدرس Subscription، شناسهٔ اختصاصی مشتری را از انتهای مثال حذف کن. نصب‌کننده دسترسی خواندن API را قبل از فعال‌کردن سرویس می‌آزماید.

بررسی اولین اجرا

ابتدا وضعیت سرویس و آخرین لاگ‌ها را ببین. سپس با حساب مالک در چت خصوصی ربات /start و /sudoadmin را اجرا کن.

Bash
systemctl status xui-bot.service --no-pager -l
journalctl -u xui-bot.service -n 100 --no-pager
  1. در «حساب واریز» شمارهٔ کارت، نام دارنده و بانک را تنظیم کن. تصویر کارت اختیاری است.
  2. در «پلان‌ها» قیمت و شرایط پلان‌های نمونه را بازبینی کن. در «تست و Inboundها» مسیر تست و هر پلان را تعیین کن.
  3. دستور /xuidiag و /groupsdiag را اجرا کن. از حساب تست، یک تست رایگان و یک خرید کامل را امتحان کن و تحویل کانفیگ را بررسی کن.

راهنمای پنل ادمین

همهٔ مسیرهای زیر از /sudoadmin شروع می‌شوند، مگر جایی که دکمه در پیام رسید مشتری باشد. عنوان هر بخش با منوی داخل ربات هماهنگ است.

بخش مرتبطی پیدا نشد.

حساب واریز، رسید و گزارش فروش
  1. در «حساب واریز» شماره و نام دارندهٔ کارت، بانک و در صورت نیاز عکس کارت را ثبت کن.
  2. وقتی مشتری رسید بفرستد، همان پیام را با مبلغ، سفارش و دریافت وجه مقایسه کن. «تأیید» ساخت یا تمدید سرویس را شروع می‌کند. «رد» برای رسید نامعتبر است.
  3. «گزارش فروش» تعداد خرید، تمدید و حجم اضافه و ریز درآمد نقدی، کیف پول و پورسانت را نشان می‌دهد.

اگر تراکنش APPROVED است ولی کانفیگ نرسیده، مشتری می‌تواند از «حساب کاربری» سرویس را باز کند و «دریافت کانفیگ‌های مستقیم» را بزند. اگر تراکنش تمدید یا حجم ISSUE است، قبل از تکرار بررسی کن سهمیه یا زمان روی پنل اعمال شده یا نه.

پلان، دسته‌بندی، حجم و نام سرویس
  1. در «پلان‌ها» قیمت به تومان، حجم برحسب GB، مدت به روز و IP Limit را وارد کن. مقدار 0 برای حجم یعنی نامحدود. مثال افزودن پلان را پایین ببین.
  2. در ویرایش پلان، ID را اول خط بگذار. از «دسته‌بندی پلان‌ها» دسته بساز و ID پلان را به آن اختصاص بده.
  3. بستهٔ حجم اضافه را از «پلان‌ها» تعریف کن. برای پلان نامحدود گزینهٔ خرید حجم نمایش داده نمی‌شود. همان‌جا می‌توانی روش نام‌گذاری سرویس را کنترل کنی.
  4. پلان دارای سابقهٔ تراکنش را غیرفعال کن تا تاریخچهٔ خرید حفظ شود.

تست، Inbound و Groups
  • «تست و Inboundها» برای خاموش یا روشن کردن تست، تعیین حجم/مدت/IP پیش‌فرض و انتخاب Inbound برای تست یا هر پلان است. بازنشانی انتخاب، همهٔ Inboundهای فعال را برمی‌گرداند.
  • پیش از اولین تست کاربر در «تست اختصاصی» فرمت Telegram ID | GB | Days | IP Limit | Note را وارد کن.
  • «Groups» تعداد کلاینت‌ها را از پنل می‌خواند. گزینهٔ ساخت و همگام‌سازی، گروه‌های مورد نیاز را ایجاد می‌کند؛ پیش‌فرض مشتریان پولی Customers و تست‌ها Trial است.
احراز، عضویت، مدیران و وضعیت فروش
  • در «احراز و عضویت» می‌توانی درخواست شمارهٔ تلگرام کاربر را برای خرید فعال کنی. برای عضویت، ربات را ادمین کانال کن و @channel یا لینک عمومی را وارد کن. برای کانال خصوصی از -1001234567890 | https://t.me/+InviteLink با مقادیر واقعی استفاده کن.
  • «بررسی دسترسی ربات» را بزن، سپس عضویت را فعال کن و با یک عضو و یک غیرعضو امتحان کن.
  • افزودن و حذف مدیر با شناسهٔ عددی از حساب مالک انجام می‌شود. «لیست سیاه» خرید و تست کاربر را محدود می‌کند؛ «غیرفعال‌کردن کاربر» او را از فهرست کاربران فعال پیام همگانی خارج می‌کند.
  • «وضعیت فروش» حالت عادی، توقف خرید/تمدید/حجم یا تعمیرات را کنترل می‌کند. در تعمیرات صدور تست هم متوقف می‌شود. حساب، راهنما و پشتیبانی همچنان در دسترس‌اند.
کیف پول، معرفی، تخفیف و هدیه
  • از «همکاری در فروش» برنامهٔ معرفی، درصد پورسانت، کاربران برتر و اصلاح موجودی کیف پول را مدیریت کن. نمونهٔ تعدیل کیف پول 123456789 | 50000 است. مقدار منفی از موجودی کم می‌کند.
  • در «کد و پاداش» کش‌بک را روشن یا خاموش کن و درصد را تنظیم کن. کد تخفیف مبلغی یا درصدی می‌تواند سقف استفاده، حداقل خرید و زمان انقضا داشته باشد.
  • کد هدیه کیف پول مشتری را شارژ می‌کند. ترتیب فیلدها در ربات نمایش داده می‌شود.

CRM، اتصال سرویس، بازخورد و پیام هدفمند
  • در CRM نظرسنجی منبع آشنایی، پیگیری بعد از پایان تست و تعداد ساعت تأخیر را تنظیم کن. کاربری که تا زمان پیگیری خرید کرده دوباره پیام پیگیری تست نمی‌گیرد.
  • برای اتصال سرویس قدیمی، مشتری نام Client را از حساب کاربری می‌دهد. اگر tgId با حساب مشتری یکی باشد اتصال خودکار است. در غیر این صورت درخواست تأیید ادمین را قبل از اجازه بررسی کن.
  • «بازخورد مشتری» امتیاز و نظرها را نشان می‌دهد. در «پیام هدفمند» گروه مخاطبان، مانند مشتریان خریدار یا کاربران تستِ بدون خرید، را انتخاب و پیام را ارسال کن.
راهنمای اتصال، ظاهر، برند و متن‌ها
  • در «راهنمای اتصال» سیستم‌عامل را انتخاب کن و متن، عکس یا ویدیو اضافه کن. ترتیب را تنظیم کن و پیش‌نمایش کاربر را ببین.
  • «متن‌ها و FAQ» پیام خوش‌آمد و سؤالات رایج را ویرایش می‌کند. «برند و منوی مشتری» نام برند و دکمه‌های قابل مشاهده را کنترل می‌کند.
  • در «ظاهر و دکمه‌ها» سبک دکمه و Custom Emoji را تنظیم کن. با /emojiid شناسه را پیدا کن و از تست داخل ربات استفاده کن.
  • «سرور مجازی ساعتی» صفحهٔ معرفی سرویس میزبانی است. کار نصب و مدیریت VPS خارج از ربات انجام می‌شود.
پنل و دامنه، اعلان، بکاپ و عملیات سرور
  • برای تغییر API، مسیر مخفی، توکن یا آدرس Subscription از «پنل و دامنه (.env)» استفاده کن. قبل از قبول خرید جدید تست اتصال زنده را اجرا کن. برای تغییر دامنه، از گزینهٔ تعویض دامنه برای به‌روزرسانی آدرس‌های ذخیره‌شده استفاده کن.
  • «اعلان سرویس» وضعیت پایش حجم و انقضا را نشان می‌دهد؛ می‌توانی پایش را روشن، خاموش یا همان لحظه اجرا کنی. «وضعیت سرور» مصرف CPU، رم، دیسک و وضعیت Xray را از پنل می‌خواند.
  • «بکاپ» ساخت نسخهٔ دستی، زمان‌بندی خودکار، ارسال تلگرامی و بازیابی SQLite را پوشش می‌دهد. «Snapshot پنل» خروجی JSON فقط‌خواندنی پنل است. «Audit Log» رخدادهای مدیریتی را نمایش می‌دهد و می‌تواند آن‌ها را به چت خصوصی ارسال کند.
  • «حذف از پنل» Client مشخص را در 3x-ui حذف می‌کند. قبل از اجرا نام دقیق Client و سفارش مرتبط را بررسی کن.

به‌روزرسانی، بکاپ و بازیابی

پوشهٔ اجرای پیش‌فرض /root/SpeedyBot و نام سرویس xui-bot.service است. دستورهای این بخش را با حساب root اجرا کن.

به‌روزرسانی

به‌روزرسان وابستگی‌ها و تست‌ها را در محیط جدا بررسی می‌کند، بعد از کد و داده نسخهٔ پشتیبان می‌گیرد و در صورت خطای راه‌اندازی برای بازگشت تلاش می‌کند. برای نصب قدیمی، ابتدا یادداشت‌های مهاجرت را بخوان.

Bash
cd /root/SpeedyBot
bash update.sh --check
bash update.sh

بازیابی دیتابیس

از منوی «بکاپ» نسخهٔ دستی بگیر و یک کپی خارج از سرور نگه دار. فایل‌های .env، speedping.db و محتویات backups/ را خصوصی نگه دار. بازیابی دیتابیس، سفارش‌ها و تنظیمات ربات را به زمان بکاپ برمی‌گرداند. بازیابی Clientهای 3x-ui جداگانه است.

Bash
cd /root/SpeedyBot
bash restore.sh /path/to/backup.db
systemctl status xui-bot.service --no-pager

رفع خطاهای رایج

برای عیب‌یابی از پیام خطا شروع کن. هنگام اشتراک‌گذاری خروجی، توکن، لینک سابسکریپشن، QR و کانفیگ مشتری را حذف کن.

ربات پاسخ نمی‌دهد

با systemctl status xui-bot.service --no-pager -l و journalctl -u xui-bot.service -n 100 --no-pager سرویس را بررسی کن. از درست بودن توکن، اتصال به تلگرام و اجرای فقط یک نمونه با همان توکن مطمئن شو.

خطای 401، 403 یا 404 پنل

/xuidiag یا «تست اتصال زنده» را اجرا کن. برای 401 یا 403، مقدار توکن و دسترسی API را بررسی کن. برای 404، Base URL، مسیر مخفی و مسیر‌دهی پراکسی معکوس را جدا بررسی کن.

نصب اولیه بعد از preflight متوقف شد

در نصب تازه ممکن است .env پیش از بررسی اتصال ذخیره شده باشد. اگر سرویس هنوز ایجاد نشده، فایل را با دسترسی خصوصی به نام پشتیبان منتقل کن و نصب را با اطلاعات درست دوباره اجرا کن. برای سرویس در حال کار از مسیر تنظیمات و به‌روزرسان استفاده کن.

بررسی عضویت کانال خطا می‌دهد

در «احراز و عضویت» روی «بررسی دسترسی ربات» بزن. اگر خطای دسترسی یا شناسه می‌بینی، ربات را در همان کانال ادمین کن و برای کانال خصوصی Chat ID عددی را بگذار. دکمهٔ «بررسی مجدد عضویت» را با حساب مشتری هم امتحان کن.

تراکنش تأیید شد ولی کانفیگ نرسید

مشتری می‌تواند از «حساب کاربری» ← سرویس ← «دریافت کانفیگ‌های مستقیم» دوباره لینک‌ها را بگیرد. اگر لینک دریافتی آدرس اشتباه دارد، آن را با Copy URL در 3x-ui مقایسه و Share Address / Public Host همان Inbound را بررسی کن.

اعلان مصرف یا انقضا نرسید

از «اعلان سرویس» گزینهٔ بررسی همین الان یا دستور /notifydiag را اجرا کن و تعداد سرویس‌های پیدا‌شده و خطاها را ببین. برای بررسی گروه‌های پنل /groupsdiag را اجرا کن.
