# بررسی SpeedyBot و مسیر توسعه نسخه ۵

تاریخ بررسی: ۲۰ آبان ۱۴۰۵ / 2026-11-11. مبنا: شاخه `main` در کامیت `9e839c2` و مستندات رسمی در زمان بررسی.

## پروژه چه کاری انجام می‌دهد؟

این پروژه یک فروشگاه و مرکز عملیات تلگرامی برای 3x-ui است. خرید با رسید بانکی یا کیف پول، صدور سرویس، تست رایگان، تمدید، حجم اضافه، لینک و QR، همکاری در فروش، کش‌بک، کد تخفیف و هدیه، پشتیبانی، دسته‌بندی، پیام هدفمند، هشدار مصرف و انقضا و بکاپ را یکجا دارد. اطلاعات مالی و تنظیمات در SQLite ذخیره می‌شوند. نصب و اجرای لینوکسی با systemd انجام می‌شود.

| بخش | مسئولیت |
| --- | --- |
| `main.py` | راه‌اندازی برنامه، مهاجرت‌ها، بازیابی درخواست‌های ناتمام، workerها و polling |
| `speedybot/core.py` | منطق اصلی خرید، تراکنش، کیف پول، مدل اولیه دیتابیس، handlerهای قدیمی و ارتباط 3x-ui |
| `speedybot/corepatch.py` | اتصال سیاست‌های جدید، منوها، routing و مانیتور به هسته موجود |
| `speedybot/context.py` | دسترسی مشترک به bot، تنظیمات، دیتابیس، مجوز مدیر و audit |
| `storage.py` | جدول‌ها و مهاجرت‌های تکمیلی، دسته‌بندی و انتخاب مخاطبان |
| `handlers.py`، `admin_handlers.py`، `admin_tools.py`، `admin_ux.py` | ثبت handlerها، پنل مدیریت، wizardها و ترتیب اجرای آن‌ها |
| `user_handlers.py`، `ui.py`، `customization.py` | حساب مشتری، کاتالوگ، بازخورد، ظاهر و برند |
| `trial.py`، `linked_services.py` | تست با تنظیم عمومی/اختصاصی و مدیریت سرویس‌های قبلی |
| `backup_manager.py`، `restore.py` | اعتبارسنجی، snapshot و بازیابی SQLite |
| `env_manager.py` | خواندن و به‌روزرسانی فایل تنظیمات |
| `ops.py`، `updates.py` | snapshot پنل، پیام گروهی و اطلاع‌رسانی نسخه جدید |
| `install.sh`، `update.sh`، `restore.sh` | نصب، ارتقا همراه rollback و بازیابی از سرور |
| `tests/` | تست رفتارهای حساس و راه‌اندازی جدا از اطلاعات واقعی |
| `docs/releases/` | آرشیو یادداشت‌های انتشار |

فایل‌های `speedping.db`، `.env`، `backups/`، محیط‌های Python و `run.sh` داده عملیاتی‌اند و نباید وارد Git شوند. نسخه‌های قبلی یادداشت‌های انتشار حفظ شده و به آرشیو منتقل شده‌اند. مسیر اجرای برنامه و نام دیتابیس برای نصب‌های قبلی حفظ شده است.

## علت واقعی شکست CI

در [اجرای ناموفق شاخه اصلی](https://github.com/roseshayan/SpeedyBot/actions/runs/37914058507)، مرحله Python syntax موفق بود. شکست در Unit tests رخ می‌داد: فایل تست هنگام import هسته، `TeleBot(None)` می‌ساخت، چون `BOT_TOKEN` در CI وجود نداشت. اگر کتابخانه تلگرام روی سیستم توسعه نصب نبود، mock جایگزین این ایراد را پنهان می‌کرد.

تست اصلاح‌شده با وابستگی واقعی، توکن ساختگی، محیط موقت و دیتابیس مستقل اجرا می‌شود. CI سازگاری نسخه‌ها و تست‌ها را با Pythonهای پشتیبانی‌شده بررسی می‌کند. تست راه‌اندازی کامل هم ثبت handlerها، ساخت منوها و مهاجرت دیتابیس تازه را بدون تماس شبکه بررسی می‌کند.

## بررسی API و وابستگی‌ها

مرجع اصلی پنل، [API کلاینت‌ها](https://docs.sanaei.dev/docs/reference/api/clients/)، [احراز هویت](https://docs.sanaei.dev/docs/reference/api/authentication/)، [سرور اشتراک](https://docs.sanaei.dev/docs/reference/api/subscription-server/) و [کد controller در کامیت بررسی‌شده](https://github.com/MHSanaei/3x-ui/blob/e535df03745c5ad003ae48e812024eb5fdc2124d/internal/web/controller/client.go) است. مسیر پایه پنل همچنان باید جداگانه از `XUI_BASE_PATH` تنظیم شود. توکن Bearer باید مقدار توکن API باشد. سرویس اشتراک نیز URL و مسیر مستقل دارد.

اصلاحات این بررسی:

- پاسخ جدید کلاینت که اطلاعات آن در `obj.client` است و پاسخ تخت قدیمی به یک ساختار تبدیل می‌شوند.
- ویرایش کلاینت فقط فیلدهای موردنیاز را می‌فرستد؛ اطلاعات کامل همه مشتریان برای یک تمدید خوانده و دوباره ارسال نمی‌شود.
- خرید حجم، نتیجه واقعی `bulkAdjust` را بررسی می‌کند؛ صرف `success=true` به معنی اعمال حجم نیست.
- تعداد واقعی تغییرات گروه‌ها خوانده می‌شود و نتیجه صفر به عنوان تغییر موفق شمارش نمی‌شود.
- endpointهای شامل ایمیل یا شناسه اشتراک URL-encode می‌شوند و JSON غیرمنتظره به خطای کنترل‌شده می‌رسد.
- مالکیت سرویس هنگام دریافت لینک و QR دوباره بررسی می‌شود؛ اشتراک مشترک هم نیازمند مالکیت همه کلاینت‌های مربوط است.
- تمدید یا افزایش حجم ناتمام پس از راه‌اندازی دوباره، بدون بررسی مدیر تکرار نمی‌شود؛ پاسخ نامشخص شبکه ممکن است بعد از اعمال تغییر رخ داده باشد.

[Telegram Bot API](https://core.telegram.org/bots/api) نیز بررسی شد. نسخه رسمی آن در تاریخ بررسی 10.4 است. آخرین نسخه پایدار کتابخانه Python الزاماً همه قابلیت‌های تازه API را ندارد؛ در نسخه نصب‌شده `send_widget` موجود نیست. متدهای فعلی ربات با کتابخانه واقعی بررسی شده‌اند. سقف دانلود `getFile` در API ابری ۲۰ مگابایت است؛ فایل بزرگ‌تر باید با ابزار بازیابی سرور منتقل شود.

وابستگی‌های مستقیم مطابق انتشارهای پایدار [pyTelegramBotAPI](https://pypi.org/project/pyTelegramBotAPI/)، [Requests](https://pypi.org/project/requests/)، [qrcode](https://pypi.org/project/qrcode/) و [Pillow](https://pypi.org/project/Pillow/) به‌ترتیب روی `4.37.1`، `2.34.2`، `8.2` و `13.0.0` تثبیت شده‌اند. حداقل Python اکنون 3.11 است. Dependabot به‌روزرسانی‌های بعدی را در PRهای گروه‌بندی‌شده پیشنهاد می‌دهد؛ وابستگی‌های انتقالی هنوز توسط pip resolve می‌شوند.

## ایرادهای عملیاتی و امنیتی اصلاح‌شده

- پاک‌کردن دستی WAL/SHM بعد از restore حذف شد؛ این فایل‌ها متعلق به SQLite هستند و ممکن است اتصال فعال هنوز به آن‌ها نیاز داشته باشد.
- بازیابی دیتابیس روی خودش رد می‌شود و snapshotها نام یکتا دارند.
- ابزار CLI برای دیتابیس نصب‌شده، سرویس را پیش از restore متوقف و پس از آن دوباره راه‌اندازی می‌کند؛ `--target` مستقل، سرویس نصب‌شده را قطع نمی‌کند.
- ذخیره `.env` اتمیک شده، ورودی نامعتبر رد می‌شود و secret دارای کوتیشن پس از راه‌اندازی دوباره درست خوانده می‌شود.
- ورودی مرحله بعدی مدیر به شناسه همان مدیر و چت بسته شده و مجوز او دوباره بررسی می‌شود.
- درخواست تست در حالت `CREATING` پس از قطع برنامه قابل تلاش دوباره می‌شود.
- کاربران غیرفعال از مخاطبان پیام هدفمند حذف می‌شوند و متن کاتالوگ در HTML escape می‌شود.
- ارتقا، وابستگی‌ها و تست‌ها را پیش از توقف سرویس در محیط جدا آماده می‌کند و محیط قبلی را برای rollback نگه می‌دارد.

قابلیت‌های فرمت اشتراک و چند نود در [مستندات رسمی پنل](https://docs.sanaei.dev/docs/) آمده‌اند؛ پیشنهادهای جدول، طراحی محصول بر اساس آن قابلیت‌ها هستند. محدودیت دکمه کپی و قابلیت‌های تازه تلگرام در [مرجع Bot API](https://core.telegram.org/bots/api#copytextbutton) توضیح داده شده‌اند.

برای وضعیت زنده، [WebSocket پنل](https://docs.sanaei.dev/docs/reference/api/websocket/) به session cookie نیاز دارد؛ Bearer موجود ربات به‌تنهایی کافی نیست. افزودن آن نیازمند طراحی احراز هویت مستقل است.

## مرز اعتبارسنجی انتشار

تست‌های خودکار از شبکه، توکن و دیتابیس تولید مستقل‌اند. عبور آن‌ها جای آزمایش روی پنل واقعی با نسخه و تنظیمات همان نصب را نمی‌گیرد. پیش از انتشار عمومی روی نصب عملیاتی، خرید آزمایشی، تمدید، حجم، دریافت لینک و QR، هشدار و یک چرخه بکاپ/restore روی محیط آزمایشی انجام شود. در عملیات تمدید/حجم با پاسخ شبکه نامشخص، بررسی پنل پیش از Retry ضروری است؛ این نسخه ادعای اجرای exactly-once بین SQLite و پنل ندارد.
