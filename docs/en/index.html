Open-source Telegram bot for 3x-ui

Run your 3x-ui store in Telegram.

SpeedyBot provisions 3x-ui services after payment approval and delivers subscription links and direct configs. Customers can check usage, renew, or contact support from their Telegram account.

What SpeedyBot handles

Sales and delivery

Card transfer with manual receipt approval or wallet checkout, free trials, service renewal, volume packs, subscription URLs, direct configs, and QR codes.

Customer account

Live traffic and expiry, purchase and wallet history, connection guides, support, and verified linking of existing panel services.

Admin operations

Plans and categories, inbound selection, channel membership, discounts and wallet gifts, referrals, CRM, service notifications, backups, and sales reports.

Install on a Linux server

Use these steps for a fresh install on Ubuntu or Debian with systemd. Ubuntu 24.04 LTS and Python 3.11 or newer are recommended. Use the updater for an existing installation.

Prepare your bot and panel

  1. Send /newbot to BotFather and store the token. Have the owner's numeric Telegram user ID ready. You can send your new bot a private message before starting it and read message.from.id in the getUpdates response.
  2. In 3x-ui, open Settings → Security → API Token and copy the full token value. Enable at least one inbound and check the Subscription address and path in the panel settings.
  3. The VPS needs outbound access to the Telegram Bot API and the panel. Customers must be able to reach the public subscription endpoint. SpeedyBot uses long polling, so it needs no inbound webhook port.

Run the installer

Switch to root with sudo -i, then run these commands on the server. The installer hides secret values as you enter them.

Bash
apt update
apt install -y git
git clone https://github.com/roseshayan/SpeedyBot.git /root/SpeedyBot
cd /root/SpeedyBot
bash install.sh

XUI_BASE_PATHHidden panel path, for example /private. Use / when the panel has no hidden path.
XUI_BEARER_TOKENRaw 3x-ui API token value
XUI_SUB_SERVER_URLPublic subscription origin, for example https://sub.example.com:2096

For https://panel.example.com:2053/private/, enter /private in the separate base-path field. Leave the customer-specific ID out of the subscription server and path. The installer checks read access to the panel API before enabling the service.

Verify the first run

Check the service and recent logs. Open your bot in the owner's private Telegram chat and send /start and /sudoadmin.

Bash
systemctl status xui-bot.service --no-pager -l
journalctl -u xui-bot.service -n 100 --no-pager

Admin Control Center guide

Start from /sudoadmin unless the action is on a customer's receipt. The Persian menu labels below match the Telegram interface.

No matching admin sections.

Payment account, receipts, and sales reports
  1. Set the card number, holder, bank, and optional card photo in Payment account (حساب واریز).
  2. When a receipt arrives, check the order, amount, and incoming payment. Approve to start provisioning or renewal. Reject invalid receipts.
  3. Sales report (گزارش فروش) shows purchases, renewals, volume packs, cash, wallet spending, and referral commissions.

If the transaction is APPROVED and configs did not arrive, the customer can open the service in their account and request direct configs. For a renewal or volume transaction in ISSUE, verify whether the panel already applied the update before retrying.

Plans, categories, volume packs, and names
  1. In Plans (پلان‌ها), enter prices in Toman, traffic in GB, duration in days, and an IP limit. Set traffic to 0 for unlimited. See the example below.
  2. Put the plan ID first when editing. Use Plan categories (دسته‌بندی پلان‌ها) to create a category and assign a plan by ID.
  3. Create volume packs and choose the naming mode under Plans. Customers with unlimited plans do not see the extra-volume action.
  4. Deactivate a plan that has transaction history to preserve purchase records.

Monthly 2-user | 350000 | 30 | 30 | 2

Trials, inbounds, and Groups
  • Use Trial & Inbounds (تست و Inboundها) to enable trials, set default traffic/duration/IP limit, and choose inbounds for the trial or each plan. Resetting a selection restores all active inbounds.
  • Before a user claims their first trial, use the custom trial menu (تست اختصاصی) and enter Telegram ID | GB | Days | IP Limit | Note.
  • Groups (Groups) reads live client counts. Create and reconcile Groups to sync the expected groups. The defaults are Customers for paid services and Trial for trials.
Verification, membership, admins, and operating mode
  • Open Verification & membership (احراز و عضویت) to require a phone number or Telegram channel membership. Make the bot an admin of the channel. Use a public @channel or public link. For private channels, supply the numeric ID and invite link, for example -1001234567890 | https://t.me/+InviteLink.
  • Run Check bot access (بررسی دسترسی ربات), enable membership, then test as a member and a non-member.
  • The owner adds or removes admins by numeric ID. Blacklist (لیست سیاه) restricts purchases and trials. Deactivate user removes a user from active-user broadcasts.
  • Sales mode (وضعیت فروش) controls normal operation, paused sales, or maintenance. Paused sales blocks purchases, renewals and volume adds. Maintenance also blocks trials. Account, guides and support stay available.
Wallet, referrals, discounts, and gifts
  • Use Affiliate (همکاری در فروش) to set the referral commission, see the leaderboard, and adjust a wallet by Telegram ID. Example 123456789 | 50000. Negative amounts deduct credit.
  • Use Codes & rewards (کد و پاداش) for cashback and fixed or percentage discounts with a minimum order, usage cap, or expiry.
  • Gift codes add to the customer's wallet. The bot displays the field order and an example for each form.

Percentage discount example WELCOME20 | percent | 20 | 200000 | 100 | 30

Wallet gift example GIFT50 | 50000 | 20 | 30

CRM, existing services, feedback, and broadcasts
  • In CRM, toggle the acquisition survey or post-trial follow-up and set the delay. Users who buy before follow-up are skipped.
  • To link an existing service, the customer supplies its panel Client name. The bot links it automatically when tgId matches. Review the claim before approving a request with a different ID.
  • Customer feedback (بازخورد مشتری) shows ratings and comments. In Targeted broadcast (پیام هدفمند), choose an audience such as paying customers or trial users who have never purchased, then send the message.
Connection guides, appearance, branding, and copy
  • In Connection guides (راهنمای اتصال), select a platform, add text, photos or video, adjust the order, and preview the guide.
  • Edit the welcome message and help text in Text & FAQ (متن‌ها و FAQ). Use Brand & customer menu (برند و منوی مشتری) to change the brand name or visible buttons.
  • Use Appearance (ظاهر و دکمه‌ها) for button styles and Custom Emoji. Run /emojiid to find an emoji ID and use the in-bot test.
  • The hourly VPS menu (سرور مجازی ساعتی) is a hosting referral. VPS installation and management happen outside the bot.
Panel and domain, notifications, backup, and server operations
  • Use Panel & domain (.env) (پنل و دامنه) to change API settings and the subscription endpoint. Run the live connection test before accepting new orders. Use domain replacement when it should update other stored URLs too.
  • Service notifications (اعلان سرویس) shows the monitoring configuration and lets you toggle or run a check. Server status reads CPU, memory, disk and Xray state from the panel.
  • Backup (بکاپ) covers manual snapshots of SQLite, automatic backups, Telegram delivery, and database restore. Panel Snapshot is a read-only 3x-ui JSON export. Audit Log records administrative events and can mirror them to a private chat.
  • Remove from panel (حذف از پنل) deletes the named 3x-ui Client. Verify the exact Client and associated order first.

Updates, backup, and recovery

The default installation path is /root/SpeedyBot and the systemd unit is xui-bot.service. Run these commands as root.

Update an existing installation

The updater stages dependencies and tests in a separate environment. It backs up the current code and data and attempts rollback on a startup failure. Review the migration notes before upgrading an older installation.

Bash
cd /root/SpeedyBot
bash update.sh --check
bash update.sh

Restore the SQLite database

Create a manual backup from the admin panel and keep an off-server copy. Protect .env, speedping.db, and backups/. Restoring the database rolls orders and bot settings back to the backup date. 3x-ui Client recovery is separate.

Bash
cd /root/SpeedyBot
bash restore.sh /path/to/backup.db
systemctl status xui-bot.service --no-pager

Troubleshoot common failures

Start with the error output. Remove tokens, subscription URLs, QR codes and customer configs before sharing it.

The bot does not respond

Check systemctl status xui-bot.service --no-pager -l and journalctl -u xui-bot.service -n 100 --no-pager. Confirm your Telegram token and connectivity, and ensure a single process polls with that token.

3x-ui returns 401, 403, or 404

Run /xuidiag or the live connection test. For 401 or 403, inspect the plaintext token and API access. For 404, check the base URL, hidden path, and reverse proxy routes separately.

The first install stopped at preflight

On a fresh install, .env can be written before connectivity verification. If no service was created yet, move the file to a private backup path and rerun the installer with corrected values. Use the settings and updater for an existing installation.

Channel membership cannot be checked

Open Verification & membership and run Check bot access. Check that the bot is an admin in the configured channel and use the numeric Chat ID for a private channel. Recheck membership from a customer account.

Purchase approved, but configs are missing

Open the service in the customer's account and choose Get direct configs. If a link points to the wrong host, compare it with Copy URL in 3x-ui and check the inbound's Share Address or Public Host.

Usage or expiry notifications did not arrive

Run a check from Service notifications or send /notifydiag. Review matched services and errors. Run /groupsdiag to check live panel groups.
